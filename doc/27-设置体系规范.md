# 设置体系规范 —— 统一入口 · 模块命名空间 · 声明式注册

> 本规范是 ARCH-2（`21-架构层改造方案.md` §ARCH-2）的**执行细则与扩展协议**，回答三个问题：
> ① 设置统一走还是按模块走；② 后续新增模块的配置怎么读、怎么写；③ 全部开关与自定义参数清单。
> 所有分册（21~26）与 `doc/2.0/` 增补模块的设置项**一律以本规范为准**；与各分册冲突时以本规范为准。

---

## 1. 决策：统一入口 + 模块命名空间

**结论：存储、API、前端入口全局统一一套；配置项按「组.键」命名空间归属各模块。模块只「声明」设置，不「实现」设置。**

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 每模块自带设置接口（`/api/memory/settings`、`/api/task/settings`…） | 模块自治 | 前端要 N 个 service；设置页手工拼接；脱敏/校验各自实现 | ❌ |
| 统一入口、裸 key 无命名空间 | 最简单 | 键冲突无人管；无法按模块归组渲染；权限/密钥规则被绕过 | ❌ |
| **统一入口 + `组.键` 命名空间 + 声明式注册** | 一套存储/API/校验/脱敏；设置页按声明自动分组；新模块接入零接口改动 | 需要一个轻量注册表（约百行） | ✅ 采用 |

**分层原则**（沿用 ARCH-2 / OPS-2 已有决策）：

| 层 | 去处 | 说明 |
| --- | --- | --- |
| 普通设置 | `app_settings` 表（key-value，value 存 JSON） | 本规范管辖 |
| 密钥 | 系统钥匙串（`services/secrets.py`） | 只进不出、脱敏回显，**不走**本规范的批量接口 |
| 安全红线 | 代码常量 | **不设开关、不开放自定义**（见 §5.3） |

## 2. 声明式注册（核心机制）

每个模块在自己包内声明 `SETTING_DEFS`，启动时合并进全局注册表：

```python
# backend/app/tools/settings_defs.py —— 示例：工具生态模块的设置声明
SETTING_DEFS = [
    SettingDef(
        key="context.max_tool_output_chars",   # 组.键，全局唯一
        type="int",                            # 类型（bool/int/float/string/json/select）
        default=8000,                          # 默认值（未落库时读默认，调用方不写 if-else 兜底）
        min=1000, max=200000,                  # 数值范围（写入校验）
        category="context",                    # 设置页分组（自动渲染，见 §4）
        since="M0",                            # 首次引入的里程碑（追溯用）
        description="单次工具输出截断阈值（字符数），超出截断并落盘可续读",
    ),
]
```

- **注册表**：`services/settings_registry.py` 持有全量 `SettingDef`，提供：
  - `GET /api/settings/meta`：下发全量 schema（类型/默认/范围/分组），**不含任何值**；
  - `get_setting(key)`：未落库 → 返回声明默认值；
  - `put_settings(dict)`：按声明逐键校验类型/范围 → 落库 → 发布变更事件。
- **变更通知**：进程内 pub/sub（`registry.publish(key, value)`），按**键前缀订阅**：
  `llm/state.py` 订阅 `llm.*` / `model.*`（agent 失效重建）、MCP client 订阅 `mcp.*`（重连）、前端主题订阅 `theme`——**事件驱动，不轮询**。
- **设置页自动分组**：前端按 `category` 渲染分区；新增模块的设置**零前端改动**自动出现。

## 3. 新模块接入三步（后续添加配置的标准路径）

以 B9 自动化模块（`doc/2.0/自动化/定时任务与watcher.md`）为例：

1. **声明**：模块内写 `SETTING_DEFS`（如 `automation.scheduler_enabled`），在注册表 import 一行。
2. **读**：模块代码 `get_setting("automation.scheduler_enabled")`——默认值来自声明，不重复硬编码。
3. **写**：**不改任何接口**——`PUT /api/settings` 天然支持新键（校验来自声明）；设置页因 `meta` 自动出现「自动化」分区。

> **禁止**：模块自建设置表 / 自开设置读写接口 / 前端为新模块单独写 settings service。

## 4. 前端约定

- Pinia `stores/settings.ts`：启动拉 `GET /api/settings`（全量值）+ `GET /api/settings/meta`（schema），提供 `get(key)` / `put(partial)`。
- 设置页按 `category` 分区渲染，取值约定：

| category | 分区名 | 内容 |
| --- | --- | --- |
| `agent` | Agent 行为 | steering / 验证闭环 / 子 agent / 拆分 / 重规划 / 迭代上限——**A 组键集中于此，设置页首屏可见** |
| `context` | 上下文 | 输出截断 / 压缩阈值 / 保留条数 |
| `cost` | 成本与保护 | 熔断三维度 / 重试参数；关闭 `cost.guard_enabled` 弹**二次确认** |
| `model` | 模型 | 既有 `llm.*` + 角色模型（B5）+ 缓存开关（B6） |
| `advanced` | 高级 | 多模型路由 / trace / 记忆参数——默认值即最优，普通用户不动 |
| （既有） | 外观 / 工作区 / 权限 | UX-2 / ARCH-3 / UX-7 沿用 |

> 不额外套 keyring，是因为 MCP server 的凭据形态千差万别（有的是 header、有的是环境变量、有的写在 args 里），
> 强行抽象只会让用户不知道该往哪填。

| `trace.keep_days` | int（0~365） | 7 | A（OPS-6） | diagnostic | 轨迹保留天数；启动时清理更早的记录，0=永不清理 |
| `ops.log_level` | select（debug/info/warning/error） | info | A（OPS-3） | diagnostic | 日志级别；改完立即生效（订阅 `ops.` 前缀） |
| `ops.auto_update_check` | bool | on | A（OPS-4） | diagnostic | 桌面版启动后是否自动检查新版本；**由 Electron 主进程在启动时读一次**，改完下一次启动生效（关掉后仍可在「关于」页手动检查） |

> `ops.auto_update_check` 是唯一一个「消费者不是 Python」的设置键：它的读取方是
> `electron/src/main/updater.ts` 的 `readAutoCheck(port)`，通过 `GET /api/settings` 拿值。
> 之所以仍然存在后端，是为了让"关掉自动更新"和别的配置一样能导入导出、也只有一份真相；
> 代价是改完要下次启动才生效（代码注释里写明了这处取舍）。

> `trace.enabled` 原本声明在内置的 `advanced` 分区，`ops_settings_defs.py` 里**重新声明**到 `diagnostic`，
> 把"开关 + 保留天数 + 日志级别"放在同一处。`register_defs` 明确允许后注册者覆盖，这是有意的用法。

### 5.8 设置项的展示信息（label / option_labels）

> 约定（M4 起强制）：**每个 SettingDef 必须有中文 `label`**；select 类型还必须给 `option_labels`
> （与 `options` 等长、顺序一致）。`test_all_settings_have_chinese_labels` 会拦住漏掉的。

| 字段 | 作用 | 为什么要有 |
| --- | --- | --- |
| `label` | 设置页的标题 | 直接把 `theme.mode` 摆给用户看是内部实现泄露 |
| `option_labels` | select 候选值的中文名 | 值本身是**存库契约**（`dark` / `merge`），不能为了显示去改它 |

前端行为：标题取 `label || key`，下拉取 `option_labels[i] || options[i]`；
`key` 仍以小号等宽字显示在标题下方，排查配置时能对得上文档。

| `memory.min_importance` | int（1~5） | 1 | A（MEM） | memory | 检索时的重要度门槛；调到 3 以上能明显减少噪声 |
| `memory.dedup_threshold` | float（0.5~1.0） | 0.85 | A（MEM） | memory | 相似度去重阈值（默认值按实测分布校准，见 doc/25 §13.2） |

**MEM 增强新增（M6 落地，`since="M6"`）**——这六条控制"向量从哪来、重复怎么处理、旧记忆何时清掉"：

| 键 | 类型 | 默认 | 时机 | category | 说明 |
| --- | --- | --- | --- | --- | --- |
| `memory.merge_enabled` | bool | on | A（M6） | memory | 近似重复时**合并进旧记忆**而不是丢弃；关掉即回到"直接丢弃"的老行为（文档正文取更长、重要度取大、`merged_count += 1`） |
| `memory.embedding_backend` | select（local / remote） | local | A（M6） | memory | 向量后端：`local` 本地哈希 2-gram（快、免费、只认字面），`remote` 调 `/embeddings` 接口（懂语义，需要密钥与网络） |
| `memory.embedding_provider` | string | 空 | A（M6） | memory | 远端后端用哪个 provider；**留空=跟随当前对话模型**的 provider（免得用户改模型后记忆向量来源悄悄变了） |
| `memory.embedding_model` | string | `text-embedding-3-small` | A（M6） | memory | 远端 embedding 模型名；换模型等于换向量空间，必须配合 `POST /api/memory/reindex` 全量重算 |
| `memory.ttl_days` | int（0~3650） | 180 | A（M6） | memory | 多少天没被用过/没更新就算过期；**0=关闭过期淘汰**。只删 `importance <= 2` 的低价值记忆 |
| `memory.max_per_workspace` | int（0~5000） | 500 | A（M6） | memory | 单工作区记忆条数上限，超了按"重要度低、从未用过、创建早"的顺序淘汰；**0=不限制** |

> 为什么淘汰要同时有 `ttl_days` 与 `max_per_workspace`：前者防"越攒越旧"（时间维度），后者防"某个工作区把库塞满"
> （容量维度）。两者都是 0 可关，因为删记忆是不可逆操作——在用户不主动整理的前提下，默认值只敢删"低重要度且长期未用"的。
>
> 为什么两个淘汰阈值都只在**低重要度**区间动手：`importance >= 3` 的记忆是用户明确认可过的结论（决策/偏好），
> 自动删掉比留一堆噪声更糟。
>
> `memory.enabled` / `memory.top_k` 原本占位在内置的 `advanced` 分区，`memory_settings_defs.py` 里**重新声明**到 `memory`，
> 与 `trace.*` 从 advanced 挪到 diagnostic 是同一种用法（`register_defs` 允许后注册者覆盖）。

### 5.11 Office 文档解析（EXT-4，✅ 已落地 A~D；E 阶段待桌面壳）

> 落地位置：`backend/app/services/office_settings_defs.py`（`register_office_defs()`，在 `main.py` 的 `create_app()` 里注册）。
> 引擎鉴权用的 `editor_sdk_token` 不进设置 —— 它是部署期配置（`backend/app/config.py` 的 `editor_sdk_token`），
> 与端口不同：端口随引擎启动而变，token 是装机时写死的。

| 键 | 类型 | 默认 | 时机 | category | 说明 |
| --- | --- | --- | --- | --- | --- |
| `office.enabled` | bool | on | A（EXT-4） | office | Office 家族（docx/xlsx/pptx 及旧版二进制）是否走本地 Office CLI；关掉后回落纯文本试读 |
| `office.port` | int（0~65535） | 0 | A（EXT-4） | office | 0=自动探测 39099–39108；固定端口须与桌面壳拉起 `editor_sdk` 时一致 |
| `office.timeout_ms` | int（1000~120000） | 15000 | A（EXT-4） | office | 单次 CLI 调用超时（毫秒）；大文件可调高 |
| `office.max_rows` | int（100~50000） | 5000 | A（EXT-4） | office | 单 sheet 最多读多少行（取代原常量 `MAX_XLSX_ROWS`） |
| `office.max_cols` | int（5~200） | 40 | A（EXT-4） | office | 单 sheet 最多读多少列（取代原常量 `MAX_XLSX_COLS`） |

> **为什么这组键必须存在**（而不是写死常量）：引擎端口与超时取决于**部署环境**（用户机器上 Office/WPS 是否可用、
> 引擎被拉起在哪个端口、大文件要等多久）。写死会让"引擎明明在 40000，后端却一直探测 39099"这种问题只能改代码。
> `office.enabled=off` 同时是**回滚开关**：关掉即回到文本试读，不需要改注册表、不需要回退版本。
>
> **口径**：这五个键只影响"读文档"，不影响 `.pdf` / 纯文本；也不放宽任何安全边界
> （解析链路的只读白名单是代码常量，不进设置）。

### 5.3 不开放项（红线，无开关、无自定义）

| 项 | 原因 |
| --- | --- |
| DENY 硬护栏（系统目录 / 越权写 / 联网外发审计） | 安全底线，任何权限模式下不可关（UX-7 已约定） |
| 密钥明文回显 / 密钥导出 | 泄露风险（ARCH-2 / OPS-5 已约定） |
| trace payload 中的密钥脱敏 | 同上 |
| SUB agent 的写操作强制 ASK | ARCH-7 安全设计，不可配置放开 |

## 6. 读写时序

```
写：前端 put(partial) ──► PUT /api/settings ──► registry 逐键校验（type/range）
      ──► setting_service 落库 app_settings ──► publish(key, value)
      ──► 订阅者：llm/state（重建 agent）· mcp client（重连）· 前端 store（刷新）

读：后端 get_setting(key) ──► 命中 app_settings ? 值 : 声明默认值
    前端启动 get() ──► GET /api/settings（值）+ GET /api/settings/meta（schema）
```
