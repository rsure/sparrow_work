> 对应总计划里程碑 **M2**（UX-1/2/3 + UX-9）、**M5**（UX-4/5）。
> **状态**：UX-1 / UX-2 / UX-3 / UX-6 ✅（M2）；**UX-4 重命名+搜索 ✅ / UX-5 ✅ / UX-7 ✅ / UX-9 ✅（M5 前半批）**；**UX-8 `@`与`/` ✅、UX-4 的置顶/归档/导出 ✅（M5 后半批，即"UX 收尾"）**。

## 1. 目标

1. 页面重构为 **CC 式三栏架构**。
2. 支持**主题定制**（背景、配色、自定义主题、明暗切换）。
3. Markdown + 代码高亮 + 文件引用跳转。
4. 会话管理增强 + Token 统计面板。
5. **快捷键**：Enter 发送 / Shift+Enter（或 Ctrl+Enter）换行，可互换。
6. **权限控制**：每次询问 / 工作区内授权 / 完全授权 三档。
7. **快捷指令**：`@` 选文件、`/` 输入命令（可扩展）。

## UX-2 主题定制

### 2.1 现状

`styles/main.css` 一套写死的深色变量，`color-scheme: dark` 硬编码。

### 2.2 设计：主题 token + 预设 + 自定义

**第一步：抽 token**。把主题抽象成一组语义变量（现有变量已接近，补全即可）：

```css
:root {
  --color-bg; --color-surface; --color-surface-2;
  --color-border; --color-text; --color-text-muted;
  --color-primary; --color-accent;
  --color-success; --color-danger; --color-warning;
  --radius; --font-size; --font-family;
  --code-theme;      /* 代码高亮主题（浅/深） */
}
```

**第二步：预设 + 自定义**。

| 能力 | 说明 |
| --- | --- |
| 预设主题 | 内置 `dark`（现状）/ `light` / 几个品牌色预设 |
| 自定义主题 | 用户逐项改 token（背景、颜色、圆角、字号） |
| 明暗切换 | 一键切换 + `color-scheme` 联动（滚动条/表单原生控件跟随） |
| 代码高亮主题 | 随明暗自动选 light/dark 高亮主题 |

**第三步：运行时应用**。`useTheme` 把当前主题写到 `document.documentElement.style.setProperty('--color-xxx', …)`；主题配置存 `app_settings`（key=`theme`），启动时读回。

## UX-5 Token / 成本统计面板

**口径：计费/统计用 API 返回的真实 usage，不用估算值**（估算只用于 ARCH-5 的压缩判断，见 `21-架构层改造方案.md`）。

- **数据来源**：模型调用后 `AIMessage.usage_metadata` 的 `input_tokens / output_tokens`（各 provider 都会填；OpenAI 流式需开 `stream_options={"include_usage": True}`，否则为空）。
- **后端**：`done` 事件补 `usage` 字段（当前只有 `elapsed/tool_calls/history_len/answer`）；每轮落库可存 `usage`，历史会话也能聚合。
- **前端**：`done` 事件累计本轮 token，按单价表换算成本，侧边栏/顶栏实时展示。
- **单价表**：每 provider/模型一条 input/output 单价（元/百万 token），存 `app_settings` 可编辑；Ollama 本地模型单价记 0。

### 验收标准

- [x] 对话结束后能看到本轮**真实** token 用量与成本（右栏「本轮」：token / 费用 / 耗时 / 模型）。
- [x] 能看到**本会话累计**（轮次 / token / 费用），数据来自按轮落库的 `usage_json`。
- [x] 成本按**当轮模型**单价折算（同一会话换过模型也能分别记账）。
- [ ] 流式 usage 的 provider 覆盖：DeepSeek 正常；OpenAI 兼容端点若不返回 usage，本轮费用显示 0（不估算，不做假数据）。

### 6.4 执行中的输入（ARCH-6 落地后的行为）

流式回答期间输入栏**不再禁用**，同一个 `Enter` 有两种含义：

| 场景 | 行为 |
| --- | --- |
| 空闲 | Enter 发送新消息（原行为） |
| 正在回答 + `agent.steering_enabled` 开 | Enter = **插话**：消息进后端会话队列，当前工具结束后追加进工具结果，下一步模型就能看到；输入栏右侧出现「插话」按钮，工具条显示「插话排队 N」。插话只在**工具边界**生效——模型一轮里不调工具时，插话不会注入，会随下一轮清空 |
| 正在回答 + `agent.steering_enabled` 关 | Enter 无反应，输入框禁用并提示「正在回答中，可以先点「终止」再输入」 |

另外，工具卡片上多了一个「取消」按钮：只对**还没出结果**的工具显示，作用是在它真正开始执行前跳过后端那次调用
（返回 `OK: 用户取消了这个操作`）。已经在执行的工具不能中途取消——后端会返回 409 并建议改用「终止」，
前端如实提示，不假装成功。三档介入的关系见 `21-架构层改造方案.md` §ARCH-6。

## UX-7 权限控制（授权粒度）

### 7.1 设计

给「有风险的操作」加三档授权粒度，映射到后端现有 `tools/policy.py` + `interrupt()` 确认链路：

| 模式 | 行为 | 后端落点 |
| --- | --- | --- |
| **每次询问**（默认） | 每次有风险操作都弹确认（现状） | `interrupt()` 照常 |
| **工作区内授权** | 某工作区首次批准后，同类操作在该工作区自动放行；跨工作区重新问 | 新增 approvals 表（workspace_id + 动作指纹 → allowed），`policy.py` 决策前查 |
| **完全授权** | 不再弹确认（系统目录等硬禁止仍拦截） | 跳过 interrupt，硬护栏不变 |

- **UI**：顶栏或设置页一个「权限模式」下拉；确认弹窗加「记住本次授权（本工作区）」勾选。
- **存储**：`app_settings` 存 `permission.mode`；`approvals` 表存工作区级授权。
- **安全红线**：无论哪种模式，系统目录 / 越权写 / 联网外发等硬护栏（`doc/01~06`）**始终生效**，模式只影响「确认弹窗」这一层。

### 7.4 后端实现细节（approval 表 + policy.py 三档判定）

> 以下精确对齐现有代码锚点：`tools/policy.py` 的 `decide()` / `make_tool()` / `SessionContext`，`tools/tool_utils.py` 的 `ask_user()`，`tools/session.py` 的 `current_context()`，`chat_controller.py` 的 `ChatResumeRequest` / `Command(resume=...)`。

#### A. 权限模式枚举（存 `app_settings`，key=`permission.mode`，默认 `ask`）

| 值 | 含义 |
| --- | --- |
| `ask` | 每次询问（现状，fail-safe 默认） |
| `workspace` | 工作区内授权：首次批准后记住，同工作区同类操作自动放行 |
| `allow` | 完全授权：跳过确认弹窗（硬护栏仍拦截） |

#### B. `entity/approval.py` 表结构

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | int PK | 自增主键 |
| `workspace_id` | str, 索引 | 工作区 id（ARCH-3 未落地前用「工作区根路径」串做临时键） |
| `tool` | str | 工具名（动作指纹第 1 维） |
| `kind` | str | 操作类型 read/write/exec/net（冗余存，仅展示/调试） |
| `target` | str | 首次授权时的目标（审计展示，**不参与匹配**） |
| `created_at` | datetime | 授权时间 |
| 唯一约束 | — | `(workspace_id, tool)` |

#### C. 动作指纹 = `(workspace_id, tool)`

匹配只比「工作区 + 工具」两个维度。**选 per-tool 而不是 per-kind**：避免「批准 `write_file` 顺带放行 `delete_index`」。后续可按需扩展 `(workspace_id, tool, 路径前缀)` 更细粒度（首版不做）。

#### D. 决策流程改造（关键：只改 ASK 分支，DENY 永不绕过）

- `decide()` **不改**——照常产出 ALLOW / ASK / DENY。DENY 的四个来源（未注册策略 / `deny_tools` / `off_by_default` / `path_decision` 越界）都在更上游，与模式无关。
- 只改 `make_tool()` 里 `decision.level is ASK` 的分支，引入 `_resolve_ask`：

```python
# make_tool 的 ASK 分支：approved = _resolve_ask(func.__name__, action, session)

def _resolve_ask(tool: str, action: Action, session: SessionContext) -> bool:
    """按权限模式决定「原本要 ASK 的操作」是否放行；返回是否批准。"""
    mode = session.permission_mode          # ask / workspace / allow
    if mode == "allow":
        return True                          # 完全授权：跳过 interrupt

    if mode == "workspace":
        # 本工作区已授权过同类操作 → 直接放行
        if approval_service.exists(session.workspace_id, tool):
            return True
        approved, remember = ask_user(tool, ..., allow_remember=True)
        if approved and remember:
            approval_service.upsert(session.workspace_id, tool, action.kind.value, action.target)
        return approved

    return ask_user(tool, ...)[0]            # ask：照旧，无「记住」选项
```

#### E. 会话上下文注入（`tools/session.py`）

- `SessionContext` 新增 `workspace_id: str = ""`、`permission_mode: str = "ask"`。
- `current_context()` 里从 `setting_service` 读 `permission.mode` 与当前 active 工作区 id；**读不到时回退 `ask`**（fail-safe 到最严），绝不让「读设置失败」变成「放行」。

#### F. confirm_required / resume 协议扩展（`chat_controller.py` + `tool_utils.ask_user`）

- `ask_user` 的 `interrupt()` payload 加 `"can_remember": bool`（仅 workspace 模式为 True）；返回值从 `bool` 改为 `(approved, remember)`。
- `ChatResumeRequest` 加 `remember: bool = False`；`_run_resume_stream` 里 `Command(resume={req.interrupt_id: {"approved": ..., "remember": req.remember}})`。
- 前端确认弹窗：workspace 模式下显示「记住本工作区授权」勾选，resume 时带上 `remember`。

#### G. 开放接口（并入 ARCH-2 设置体系）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| PUT | `/api/settings`（含 `permission.mode` 字段） | 读写权限模式（复用 ARCH-2 通用设置） |
| GET | `/api/settings/approvals` | 列出当前工作区授权（可选） |
| DELETE | `/api/settings/approvals/{tool}` | 撤销某条授权（可选） |

#### H. 安全不变量（验收底线）

- **DENY 永远先于模式判断**：`decide()` 第 1~4 步命中 DENY 时，任何模式都不放行；模式只作用于「原本会 ASK」的决策。
- READ 类本就走 ALLOW，不受模式影响。
- `ask` 是 fail-safe 默认：读不到模式/工作区时回退 `ask`。

## UX-8 快捷指令（`@` 文件 / `/` 命令）

### 8.1 设计

| 触发 | 行为 | 数据源 |
| --- | --- | --- |
| `@` | 弹出文件选择（复用 FileTree + 工作区 + 文件名搜索），选中插入路径标记 | 工作区文件列表 |
| `/` | 弹出命令列表（复用 EXT-1 泛化后的 slash command / skill 注册表），如 `/doc`、`/记忆`、skill 名 | 后端命令注册表 |

- **可扩展**：候选来自后端（skill 注册表、工作区文件列表），新增能力不用改输入框。
- 与现有 `\doc` 的关系：`\doc` 是「内置指令」，这里把它纳入统一 `/` 命令菜单；`/doc` 与 `\doc` 等价（EXT-1 泛化时对齐）。

**增补：输入栏模型快速切换**。原方案模型选择只在顶栏（UX-1）与设置页——对话进行中切换要离开输入焦点，且无命令式入口。补两条：

| 入口 | 行为 |
| --- | --- |
| 输入栏模型 chip | 输入栏左下角常驻当前模型名，点开下拉（列表 = 内置 ∪ 自定义，按 provider 分组，数据来自 ARCH-1 §1.5.A）；选中即切换 |

**切换语义（必须遵守）**：
1. 只影响**下一轮**消息：进行中的流不中断、不换模型；
2. 会话不迁移：当前会话继续发消息即用新模型，历史轮次保留原模型标记（`done.model`，ARCH-1 §1.5.D）；
3. 三处同步：输入栏 chip / 顶栏选择器（UX-1）/ 设置页，任一处切换即时同步（走 `27-设置体系规范.md` 的设置变更事件）。

## UX-9 预算熔断（成本保护）—— 增补：改造前必须定稿（与 UX-7 同批）

> **为什么必须在改造前**：熔断判定嵌在 `policy.py` 的决策链（`make_tool`）里，与 UX-7 三档授权改的是
> 同一段代码。分两批做 = 二次动 policy、二次回归。数据源复用 UX-5 的 usage 统计。
> 原则：**统计（UX-5）只看不拦，熔断（UX-9）负责拦。**

### 设计

三个维度、以「单任务」（一轮用户请求到 `done`）为口径：

| 维度 | 键（见 `27-设置体系规范.md`） | 默认 | 超限行为 |
| --- | --- | --- | --- |
| token | `cost.max_tokens_per_task` | 500000 | 下一次工具调用前暂停，弹「继续 / 停止」 |
| 费用 | `cost.max_cost_per_task` | 5.0 元 | 同上（按 UX-5 单价表折算） |
| 时长 | `cost.max_duration_minutes` | 30 分钟 | 同上 |

- **判定位置**：`make_tool()` 在每次工具调用前查本轮累计值（累计 usage / 开始时间注入 UX-7 改造后的 `SessionContext`）。**只拦工具调用，不拦纯文本生成**——无工具的循环烧不了多少，拦不住也没有必要。
- **超限事件**：新增 SSE `budget_exceeded`（负载含三维度当前值与阈值），前端弹「继续 / 停止」——**复用 confirm_required / resume 链路**，不新开协议。
- **防骚扰**：用户选「继续」后，本轮内该维度不再重复拦截。
- **关闭保护需二次确认**：`cost.guard_enabled` 设为 off 时，设置页弹危险操作确认弹窗。
