# B10 后台任务队列（增补：改造后可动态加入）

> 依赖锚点：**ARCH-6 steering 必须先落地**（取消协议是安全前提）。
> 价值：跑几十分钟的长任务不占当前会话，可并行多个。

## 1. 设计

- **实体**：`background_task`：`(id, session_id, prompt, workspace_id, status[queued|running|done|failed|cancelled], progress, result_session_id, created_at)`。
- **提交**：对话里「转后台」按钮（当前请求移入队列），或从自动化（B9）/ 新建入口直接提交。
- **执行**：`asyncio.Queue` + 单 worker（首版并发 1，避免工具写冲突）；走独立会话 + 完整 agent 链路；无人值守 ASK 策略同 B9。
- **进度**：复用 TASK 的 `plan` / `task_start` / `task_end` 事件写入任务记录；侧边栏「任务」区实时展示。
- **取消**：ARCH-6 的停止协议作用于后台任务；取消后已产生的部分结果保留（不删会话）。
- **与 TASK 联动**：judge=complex 的任务默认询问「前台执行还是转后台」。
- **恢复**：应用重启后 queued / running 的任务标记为 interrupted 并提示，**不静默丢失**。

## 2. 改动文件

| 动作 | 文件 | 内容 |
| --- | --- | --- |
| 新增 | `backend/app/entity/background_task.py` + `services/task_queue_service.py` | 实体 + 队列 worker |
| 新增 | `backend/app/controllers/task_queue_controller.py` | 提交 / 列表 / 取消 / 进度（SSE 或轮询） |
| 扩展 | 前端侧边栏 | 「任务」区 + 「转后台」按钮 |

## 3. 验收标准

- [ ] 长任务转后台后，当前会话立即可用；后台完成后通知并可查看结果会话。
- [ ] 取消后台任务立即生效，部分结果保留。
- [ ] 应用重启后中断任务有明确标记，不静默丢失。
