# B5 多模型分工（增补：改造后可动态加入）

> 依赖锚点：ARCH-1 `llm/factory.py`。落地后纯配置化，新角色零代码改动即可扩。

## 1. 设计

- **角色模型表**（`app_settings`，走 27 规范声明式注册，category=`advanced`）：

| 键 | 用途 | 默认 |
| --- | --- | --- |
| `model.judge_model` | TASK 强度分析 / 重规划判定 | 空 = 用主模型 |
| `model.summary_model` | TASK 汇总 / ARCH-5 压缩摘要 | 空 = 用主模型 |
| `model.extract_model` | MEM 记忆抽取 | 空 = 用主模型 |

- 值格式：`provider_id/model_name`（如 `deepseek/deepseek-chat`）；空串回退主模型。
- **开关** `model.multi_model_routing`（默认 off）：关闭时全部角色用主模型，行为与现状一致。
- factory 提供 `build_chat_model_for_role(role)`：内部查表 → 未配置时直接返回主模型实例（复用 ARCH-1 实例缓存，不重复建）。
- 消费点集中在三处：`task_planner.py`、`context_manager.py`、`memory_service.py`——其余代码不感知角色概念。

## 2. 改动文件

| 动作 | 文件 | 内容 |
| --- | --- | --- |
| 扩展 | `backend/app/llm/factory.py` | `build_chat_model_for_role()` 角色构建入口 |
| 扩展 | `backend/app/services/task_planner.py` / `context_manager.py` / `memory_service.py` | 裸模型改从角色入口取 |
| 扩展 | 前端设置页 | 「高级」区模型角色选择器（按 meta 自动渲染） |

## 3. 验收标准

- [ ] judge 配便宜模型后，拆分任务成本显著下降（UX-5 面板可对比），拆分质量不劣化（用 B8 eval 验证）。
- [ ] 角色模型配置错误（如 provider 未配密钥）时，回退主模型并记日志，不崩。
- [ ] 关闭 routing 后所有角色走主模型，行为与现状一致。
