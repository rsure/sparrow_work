# 面试题库（一面技术面 · 1~3 年 · AI 应用工程）

> 本目录是 `sparrow_work` 的面试题库：三份分端卷 + 一份提示词专卷 + 一份跨端加分卷 + 一份 agent 使用卷。
> 定位是**面试官用的口述面题库**，不是笔试考卷；多数题锚定仓库真实代码（Agent 卷锚技能名与场景，见六），可共享屏幕指着问。

## 三、每题字段

每题固定六段（提示词卷为五段，见下）：

1. **标题行**：`题号｜难度｜题型｜分堆｜锚点`
2. **题**：面试官照着念的一句话
3. **口语答案**：3~5 句，面试官要听到的要点（不是教科书段落）
4. **关键听到**：2~3 个加粗关键词，现场打勾
5. **追问**：1~2 层，写成「追问：…（答：…）」
6. **常见错答**：1 句，指出背结论/答不到点上的表现

提示词卷（`05-prompt.md`）为五段：`场景 → 问 → 构造答案（讲构思） → 关键听到 → 追问`，去掉「常见错答」，因为开放题追问比纠错有价值。

实操题（`06-agent.md` 的 AG-16）在六段之外多一张「评分点」清单，现场边做边勾。

## 四、难度与评分

| 难度 | 含义 | 用法 |
| --- | --- | --- |
| L1 | 基础概念、能读懂代码 | 答不出即硬性不合格 |
| L2 | 主力题：能解释取舍、能指出坑 | 决定是否通过 |
| L3 | 超出 1~3 年水位，加分 | **不作淘汰依据** |

评分只看「关键听到」是否命中，不看表达是否漂亮；命中 2/3 记通过，命中 3/3 记优秀。答错但能说清「我会怎么验证」的，按 L2 通过。

## 五、一面怎么抽题（60~90 分钟）

1. 先按岗位选卷（后端 → Python 卷或 Java 卷；前端 → Vue 卷）；全栈岗再补跨端卷。要考「会不会用 agent 把需求跑完」，再抽 `06-agent.md`。
2. 从**必答题池**（分端卷各 12 道、Agent 卷 6 道）里抽 6~8 道（覆盖基础 → 读代码 → 设计）。
3. 从**抽答题池**（分端卷各 20 道、Agent 卷 7 道）里按候选人简历挑 6~8 道（做过 Agent 的挑 Agent，做过前端流式的挑 SSE）。
4. 时间富余再抽**加分 3~5 道**，观察上限。
5. 提示词卷可穿插：任何一道 LLM 题之后接 1 道 PR 场景题，考察「能不能把想法讲清楚」。

## 六、维护约定

- **代码会动，行号会漂**：锚点只是导航，题干与答案必须能脱离行号独立成立；改完代码请抽查锚点是否仍指向同一函数。
- **新增题优先复用真实代码**：本题库的价值在「能打开仓库指着问」，通用八股题控制在 10% 以内。
- **不重复考点**：同一考点（如 SSE 帧切分）只保留一题，细分能力用追问覆盖。
- **跨卷允许同题不同角度**：「停止生成」在 Python 卷问怎么真停、在 Vue 卷问交互取舍、在 Java 卷问为什么只能停止转发、在跨端卷问两套语义怎么对齐——这是同一能力的四个观测面，不算重复，但**同一卷内**不许重复。
- **Java 卷锚点写法**：为控制行宽用了 `backend_java/.../` 省略包前缀（展开规则写在 `03-java.md` 文件头），类名与方法名都是真的；其它四份卷用仓库相对完整路径。
- **Agent 卷锚点**：没有业务代码可指，所以锚点三类混用——仓库真实文件 / 技能名（`/to-spec` 这类）/ 场景；不编行号，写法见 `06-agent.md` 卷头。
- **改题要同步三处**：题干、口语答案、关键听到；只改其一会让面试官照着念时对不上。
- 提示词卷的场景来自真实业务（本项目、银行、客服、在线学习平台），新增场景时保持「有明确失败模式可讨论」。
