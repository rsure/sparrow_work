# 04 · AI 代码生成规范（backend_java）

> 本文件是 `AGENTS.md` 三条硬性要求在 Java 侧的落地版本。
> 任何人（包括 AI 助手）在 `backend_java/` 新增或修改代码，都必须满足本文件。
> 评审时逐条检查，不合规的代码退回重写。

---

## 1. 一句话原则

**代码首先是给人读的，其次才是给编译器跑的。**

对本项目来说，“能跑”只是及格线；学习者打开文件后能否在 30 秒内明白
“这个类为什么存在、这个字段是什么、这个方法做完会发生什么”，才是合格线。

---

## 2. 五条硬性要求

### R1 · 每个字段都要说明用途

适用对象：

- 类字段（`private final ...`）；
- record 的每个组件；
- 枚举常量；
- 常量（`static final`）；
- 配置项。

写法：

- 类字段：字段上方 `/** ... */`；
- record：类 Javadoc 用 `@param` 逐个说明；
- 枚举常量：行尾 `//` 或上方 `/** ... */`；
- 常量：上方 `/** ... */`，并写单位/取值范围。

示例：

```java
/**
 * 健康检查返回体。
 *
 * @param status        健康状态：ok=正常；degraded=降级
 * @param uptimeSeconds 本次进程已运行秒数
 */
public record HealthData(
        // 健康状态：当前实现恒为 ok
        String status,
        // 已运行秒数：保留 3 位小数
        @JsonProperty("uptime_seconds") double uptimeSeconds
) {
}
```

**禁止**：

- `private String status;` 没有任何说明；
- “status：状态”这种同义反复；
- 只写类型不写取值范围（如 `int mode` 不写 0/1/2 各代表什么）。

---

### R2 · 每个方法都要说明用途

适用对象：

- 所有公开/私有方法；
- 构造器；
- `@Bean` 方法；
- 测试方法；
- 枚举里的辅助方法。

写法：方法上方 Javadoc，至少包含：

1. **它做什么**（不是把方法名翻译一遍）；
2. 参数含义（`@param`）；
3. 返回值含义（`@return`）；
4. 可能抛出的异常（`@throws`）。

示例：

```java
/**
 * 按优先级解析出该供应商可用的 API 密钥。
 *
 * <p>优先级：显式传入 > 系统钥匙串 > .env 历史配置。</p>
 *
 * @param providerId 供应商 id
 * @param explicit   调用方显式传入的密钥
 * @return 密钥字符串；确实没有配置时返回 null
 */
private String resolveApiKey(String providerId, String explicit) {
    ...
}
```

**禁止**：

- `/** 获取数据 */`
- `/** 设置名称 */`
- 只写 `@param` 不写方法用途。

---

### R3 · 每个 import 都要说明用途

写法：import 行尾 `//` 注释，说明“在本文件里它承担什么职责”。

```java
// Spring Web 注解：声明 REST 控制器
import org.springframework.web.bind.annotation.RestController;
// 项目内统一响应外壳：所有接口返回同一种 JSON 形状
import com.example.backendjava.common.ApiResponse;
// 标准库：List 用于供应商清单
import java.util.List;
```

**禁止**：

- `// 引入 Spring`（太笼统）；
- `// 导入 List`（同义反复）；
- 一组 import 完全不写注释。

---

### R4 · 文件顶部要有模块说明

Java 用文件头 Javadoc 或 `// 模块说明：...`：

```java
// 模块说明：对话接口。路径与 Python 侧 /api/chat/* 完全一致。
package com.example.backendjava.controller;
```

包级别的说明放在 `package-info.java`。

---

### R5 · 重要判断必须解释“为什么”

以下位置必须有注释：

- `if` / `else` 的业务分支；
- `try/catch` 的 catch 块（为什么吞掉/为什么转换）；
- 循环的终止条件；
- 空值/边界值保护；
- 并发控制；
- 任何“看起来可以删掉，但其实不能删”的代码。

示例：

```java
// 只有显式配置了温度才覆盖默认值，null 表示“不干预”
if (spec.temperature() != null) {
    builder.temperature(spec.temperature());
}
```

```java
// getIfAvailable() 只在恰好一个 Bean 时返回；没有实现时返回 null
T service = provider.getIfAvailable();
if (service == null) {
    throw new ApiException(501, feature + " 尚未实现...");
}
```

**禁止**：

- 空的 catch 块没有说明；
- 魔法数字没有解释；
- 复杂条件没有拆解。

## 3. 命名与结构约定

### 3.1 包结构

按**分层**分包，不按业务域分包：一个业务域会同时落到 controller / service / dto 三个包。

```text
com.example.backendjava
├─ controller      XxxController：只做协议适配
├─ service         XxxService 接口 + Agent/工具/模型的业务契约
│  └─ impl         XxxServiceImpl：接口实现
├─ dto             XxxDtos 容器（内嵌 record）+ 少量共享结构
├─ entity          数据实体（当前为空：schema.sql + JdbcTemplate）
├─ config          配置属性与基础设施 Bean
├─ common          ApiResponse / PageResult / ApiException / 全局异常 / ToolPolicy
└─ util            与业务无关的静态工具
```

新增一个业务域时，按层各放一个文件：`controller/XxxController`、`service/XxxService`、
`dto/XxxDtos`，需要实现时再补 `service/impl/XxxServiceImpl`。
不要新建 `chat/` 这类业务域子包。

### 3.2 命名

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 类 / record | PascalCase | `ChatController` |
| 方法 / 字段 | camelCase | `listSessions` |
| 常量 | UPPER_SNAKE_CASE | `DEFAULT_CONTEXT_WINDOW` |
| 包 | 全小写 | `com.example.backendjava.controller` |
| DTO | `XxxDtos` 内嵌 record | `ChatDtos.ChatRequest` |
| Service | `XxxService` 接口（`service`）+ `XxxServiceImpl` 实现（`service.impl`） | `SettingsService` / `SettingsServiceImpl` |
| Controller | `XxxController` | `ChatController` |

### 3.3 JSON 字段

- 对外 JSON 统一 `snake_case`；
- Java 内部用驼峰；
- 用 `@JsonProperty("session_id")` 映射；
- 不要为了省注解把 Java 字段写成 snake_case（违反 Java 命名习惯）。

## 4. 分层写法

### 4.1 Controller

```java
/**
 * 对话接口。
 *
 * <p>为什么返回裸 JSON：前端 chatJson() 直接读取裸对象，Python 侧也是如此。</p>
 */
@RestController
@RequestMapping("/chat")
public class ChatController {

    /** 对话服务；当前工程只提供接口，学习者实现后自动被找到。 */
    private final ObjectProvider<ChatService> chatService;

    /**
     * 构造器注入可选 Service。
     *
     * @param chatService Spring 的按类型查找器
     */
    public ChatController(ObjectProvider<ChatService> chatService) {
        this.chatService = chatService;
    }

    /**
     * 最近会话列表。
     *
     * @param limit 最多返回多少条，默认 20
     * @return 会话列表
     */
    @GetMapping("/sessions")
    public ChatDtos.ChatSessionList listSessions(
            @RequestParam(defaultValue = "20") int limit
    ) {
        return ServiceSupport.require(chatService, "对话服务").listSessions(limit, "", false);
    }
}
```

要求：

- Controller 不写业务；
- 不直接 import LangChain4j / LangGraph4j；
- 统一用 `ServiceSupport.require(...)`；
- 每个方法都有 Javadoc。

### 4.2 Service 接口

```java
/**
 * 对话服务接口。
 *
 * <p>实现建议：StreamingChatModel + LangGraph4j + SQLiteSaver。</p>
 */
public interface ChatService {

    /**
     * 发起一次流式对话。
     *
     * @param request 已补齐默认值的对话请求
     * @return SSE 发射器
     */
    SseEmitter stream(ChatDtos.ChatRequest request);
}
```

要求：

- 接口只写领域方法，不暴露第三方类型（`SseEmitter` 是 Spring MVC 类型，可接受）；
- 每个方法说明“做什么 + 参数 + 返回”。

### 4.3 Service 实现

```java
@Service
public class DefaultChatService implements ChatService {

    /** 模型服务：统一创建 ChatModel / StreamingChatModel。 */
    private final LlmService llmService;

    /**
     * 构造器注入。
     *
     * @param llmService 模型服务
     */
    public DefaultChatService(LlmService llmService) {
        this.llmService = llmService;
    }

    @Override
    public SseEmitter stream(ChatDtos.ChatRequest request) {
        // 具体实现...
    }
}
```

要求：

- 依赖通过构造器注入，不用字段注入；
- 不在方法里 new 第三方客户端；
- 关键分支写注释。

### 4.4 DTO

```java
/**
 * 对话域 DTO 集合。
 */
public final class ChatDtos {

    /** 工具类禁止实例化。 */
    private ChatDtos() {
    }

    /**
     * 发起一次对话的请求体。
     *
     * @param message 用户输入文本
     * @param sessionId 会话 id；为空时由服务端生成
     */
    public record ChatRequest(
            // 用户输入文本
            @NotBlank(message = "message 不能为空")
            String message,
            // 会话 id；首轮不传
            @JsonProperty("session_id") String sessionId
    ) {
    }
}
```

要求：

- DTO 只承载数据；
- 每个组件都有 `@param` + 行尾注释；
- 需要默认值的，在 record 里写 `withDefaults()` 并说明。

## 5. 异常与日志

### 5.1 业务异常

```java
// 资源不存在：用业务码 404，而不是直接抛 RuntimeException
throw new ApiException(404, "document not found");
```

- 可预期错误用 `ApiException`；
- 未实现用 501；
- 未知异常交给 `GlobalExceptionHandler`，不要在 Controller 里 catch 后返回 500。

### 5.2 日志

```java
// 本类日志器：记录未预期异常与关键状态变化
private static final Logger log = LoggerFactory.getLogger(DefaultChatService.class);
```

- 不要用 `System.out.println` 打业务日志（启动横幅除外）；
- 不要打印密钥、完整文件内容、用户隐私；
- 错误日志带上下文（sessionId、provider、model），但不要带完整堆栈给前端。

## 6. 测试代码同样适用

测试文件也要满足 R1~R5：

```java
/**
 * 健康检查集成测试。
 */
@SpringBootTest
@AutoConfigureMockMvc
class HealthControllerTest {

    /** Spring MVC 测试入口；由 @AutoConfigureMockMvc 注入。 */

    private MockMvc mockMvc;

    /**
     * 验证 GET /api/health 返回统一外壳与 Java 运行时信息。
     *
     * @throws Exception MockMvc 执行失败时抛出
     */
    @Test
    void healthShouldReturnOk() throws Exception {
        ...
    }
}
```

## 7. 禁止清单

- ❌ 没有注释的字段 / 方法 / import；
- ❌ `/** 获取数据 */` 这类零信息注释；
- ❌ 魔法数字（如 `if (x > 30000)`）没有解释；
- ❌ 空的 catch 块；
- ❌ Controller 里写业务逻辑；
- ❌ 在 Service 里直接返回 `ResponseEntity`；
- ❌ 把密钥写进日志、异常信息或代码；
- ❌ 用 `System.out.println` 打业务日志；
- ❌ 为了“简洁”把 3 个类塞进一个文件（DTO 的嵌套 record 除外）；
- ❌ 不经 `LlmService` 自己 new 模型；
- ❌ 用字段注入（`@Autowired` 直接标字段）。

## 8. AI 生成代码时的提示词模板

把下面这段连同任务一起发给 AI：

```text
你在本仓库的 backend_java/ 下写 Java 代码，必须遵守：
1. 每个字段、record 组件、枚举常量都要有中文 Javadoc/行尾注释，写清是什么、单位/取值范围。
2. 每个方法/构造器都要有中文 Javadoc，写清“做什么、参数、返回、异常”，禁止只翻译方法名。
3. 每条 import 行尾都要有中文注释，说明在本文件里承担什么职责。
4. 文件顶部要有“模块说明”。
5. 重要 if/else、catch、边界判断、并发控制必须有“为什么”的注释。
6. 分层：Controller 只做协议适配；业务在 Service；不直接 new 模型/图。
7. JSON 字段用 snake_case，Java 字段用驼峰 + @JsonProperty。
8. 不要引入新依赖，除非先说明理由并更新 pom.xml 注释。
9. 不要写密钥、不要打印密钥。
10. 先给文件清单和改动点，再写代码。
```
