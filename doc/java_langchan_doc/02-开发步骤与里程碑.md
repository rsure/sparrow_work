# 02 · Java 后端开发步骤与里程碑

> 本文把“仿写 Python 后端”拆成可验收的阶段。
> 每个阶段都给出：目标、要动的文件、要实现的接口、验收标准、测试命令。
> 建议严格按顺序做，不要一上来就写 LangGraph4j 图。
>
> **⚠️ 本文是「里程碑视角」，不是动手手册。** 真正逐步照抄的代码在
> [07-手把手实施计划](./07-手把手实施计划.md)：它按「先跑通事件管道 → 再做确认恢复 →
> 再补 13 个空方法 → 最后才考虑图」的顺序展开，每个文件都有完整代码。
> 两者冲突时**以 07 为准**（07 是照着当前代码逐行核过的）。


## P2 · 设置 + SQLite（建议先做）

### 目标

先把“配置”与“持久化”跑通，后面的模型、RAG、会话都依赖它。

### 要实现的接口

`service/SettingsService`：

- `getSettings()` / `saveSettings(...)`
- `getSettingsMeta()`（可以先返回空列表）
- `getWorkspacePaths()` / `setWorkspacePaths(...)`
- `listWorkspaces()` / `createWorkspace(...)` / `updateWorkspace(...)` /
  `deleteWorkspace(...)` / `activateWorkspace(...)`
- `exportSettings()` / `importSettings(...)`
- `getSecretStatus()` / `putSecret()` / `deleteSecret()`

### 实现建议

1. 用 `JdbcTemplate` 读写 `app_settings`；
2. 值统一存 JSON 字符串，读取时用 Jackson 反序列化；
3. 工作区整体存成 `workspaces.list` 一个 JSON 数组（与 Python 一致）；
4. 密钥先存内存或环境变量；后续再接 Windows Credential Manager。

### 验收

```bash
curl http://127.0.0.1:8000/api/settings
curl -X PUT http://127.0.0.1:8000/api/settings \
  -H "Content-Type: application/json" \
  -d '{"values":{"llm.provider":"deepseek"}}'
```

重启后值仍在（SQLite 落库）。

## P4 · 对话 SSE（内存版）

### 目标

先不接图，用最简单的“模型直答”跑通 SSE，确认前端事件协议。

### 要实现

`service/ChatService` 的（实现类放 `service/impl`）：

- `stream(ChatRequest)`
- `stop(...)`
- `sessionInfo(...)`
- `clearSession(...)`
- `events()`

### 实现建议

1. `SseEmitter` 超时设为 0（不超时），由业务关闭；
2. 用 `StreamingChatModel.chat(request, handler)`，在 `onPartialResponse` 里发 `token`；
3. `onCompleteResponse` 里发 `done`；
4. `onError` 里发 `error`；
5. 会话状态（是否在跑、停止标记）先用 `ConcurrentHashMap`；
6. 历史消息先不落库，只放内存。

### 验收

前端输入一句话，能看到逐字输出；点“终止”能收到 `stopped`。

### 常见坑

- `SseEmitter` 必须在请求线程里创建，不能跨线程复用；
- 发送事件前判断 `emitter` 是否已完成，避免 `IllegalStateException`；
- 代理/网关会缓冲 SSE，响应头要加 `Cache-Control: no-cache`。

## P5 · LangGraph4j 图 + 检查点 + 中断恢复

### 目标

把 P4 的“直答”换成真正的 Agent 图，并支持“写盘前确认”。

### 要实现

- `service/AgentRuntime` 的实现类（建议放 `service/impl`，命名 `LangGraphAgentRuntime`）；
- `service/ChatService` 的 `resume(...)`；
- `AgentGraphConfig` 已提供 `BaseCheckpointSaver`，直接注入即可。

### 实现步骤

1. 定义状态：`MessagesState<ChatMessage>` 或 `AgentState` 子类；
2. 建图：
   ```java
   var graph = new StateGraph<MessagesState<ChatMessage>>(MessagesState::new)
       .addNode("agent", AsyncNodeAction.node_async(this::agentNode))
       .addNode("tools", AsyncNodeAction.node_async(this::toolsNode))
       .addNode("confirm", AsyncNodeAction.node_async(this::confirmNode))
       .addEdge(GraphDefinition.START, "agent")
       .addConditionalEdges("agent", this::routeAfterAgent, Map.of(
           "tools", "tools",
           "confirm", "confirm",
           "end", GraphDefinition.END))
       .addEdge("tools", "agent")
       .addEdge("confirm", "agent")
       .compile(CompileConfig.builder()
           .checkpointSaver(saver)
           .interruptBefore("confirm")
           .recursionLimit(25)
           .build());
   ```
3. 每次请求：
   ```java
   var config = RunnableConfig.builder().threadId(sessionId).build();
   graph.stream(Map.of("messages", List.of(userMessage)), config);
   ```
4. 恢复：
   ```java
   graph.stream(GraphInput.resume(Map.of("approved", true)), config);
   ```
5. 把 `NodeOutput` 转成 `AgentEvent`，再写 SSE。

### 验收

1. 普通问题：图跑完，`done` 事件带答案；
2. 触发写盘工具：收到 `confirm_required`，流结束；
3. 确认后调用 `/chat/resume`：图从暂停处继续；
4. 重启后端后，同一 `sessionId` 仍能恢复（SQLite 检查点）。

### 常见坑

- **threadId 必须一致**：首次执行与恢复必须用同一个 `sessionId`；
- **中断在节点边界**：工具内部的确认要包成 confirm 节点；
- **recursionLimit**：太小会在多轮工具调用时抛异常；
- **检查点与业务库同文件**：SQLite 写锁需要连接池 1 条。

## P6 · 工具集

### 目标

把 Python 的原子工具迁到 Java，并按策略控制写操作。

### 建议顺序

1. `read_file` / `list_dir` / `glob`（只读）
2. `write_file` / `edit_file`（写，需确认）
3. `run_command`（执行，需确认）
4. `sql_query`（只读 SQL）
5. `web_search` / `web_fetch` / `http_request`（默认关闭）
6. `rag_search` / `index_path`（依赖 P7）
7. `skill` / `dispatch_subagent`（依赖 P9）

### 每个工具的固定结构

```java
@Component
public class ReadFileTool implements AgentTool {
    public String name() { return "read_file"; }
    public String description() { return "读取单个文件的文本内容"; }
    public ToolPolicy policy() { return ToolPolicy.READ_ONLY; }
    public ToolResult execute(Map<String, Object> args) { ... }
}
```

### 验收

- 只读工具直接执行；
- 写盘/执行工具先触发 `confirm_required`；
- 拒绝后模型能收到 `FAIL: 用户拒绝...` 并如实转述；
- 子 Agent 作用域看不到写盘/执行/联网工具。

## P7 · RAG

### 目标

支持文档入库、检索、删除、重建索引。

### 要实现

`service/RagService` 的全部方法（实现类放 `service/impl/RagServiceImpl`）。

### 实现步骤

1. 文档解析：按扩展名分派 PDF / DOCX / TXT / Markdown；
2. 切块：500 字、重叠 80 字（与 Python 对齐）；
3. 向量化：用 `EmbeddingModel`；
4. 存储：`rag_document` + `rag_chunk`，向量先存 JSON 字符串；
5. 检索：余弦相似度 + topK + 阈值 + doc/source 过滤；
6. 重建索引：从 `rag_chunk` 读向量，重建 `InMemoryEmbeddingStore`。

### 验收

```bash
curl -X POST http://127.0.0.1:8000/api/rag/documents \
  -H "Content-Type: application/json" \
  -d '{"path":"D:/docs/a.md"}'
curl -X POST http://127.0.0.1:8000/api/rag/search \
  -H "Content-Type: application/json" \
  -d '{"query":"项目目标","top_k":5}'
```

### 注意

- 没有 FAISS；不要照搬 `faiss_index/`；
- embedding 模型的维度必须与库里已有向量一致，换模型要重建索引；
- 大文件解析要限大小，避免内存打爆。

## P8 · MCP

### 目标

连接外部 MCP Server，把工具动态挂到 Agent。

### 要实现

`service/McpService`：

- `snapshot()`
- `reload()`
- `test(config)`

### 实现建议

1. 用 `DefaultMcpClient` 建连接；
2. 用 `McpToolProvider` 转成 LangChain4j Tool；
3. 工具名加 server 前缀；
4. 单个 server 失败只记录错误，不影响其它 server；
5. reload 后清 Agent 缓存。

### 验收

配置一个 stdio MCP server，`/api/mcp/servers` 能看到工具数；
Agent 能调用其中一个工具。

## P10 · 打包

### 目标

让安装包自带 Java 后端。

### 步骤

1. `pnpm run build:backend:java` 生成并同步 jar；
2. 准备精简 JRE：
   ```bash
   jlink --add-modules java.base,java.logging,java.sql,java.naming,java.desktop \
         --output electron/resources/backend/jre
   ```
   （实际模块集合按运行时报错逐步补；也可以先用完整 JDK 验证）
3. `pnpm run dist:win`；
4. 在 `electron/dist/win-unpacked/resources/backend/` 确认：
   - `backend-java.jar`
   - `jre/bin/java.exe`（可选）
   - `backend.config.json`（在 resources/ 根目录）

### 验收

在没装 JDK 的机器上运行安装包，健康检查通过。

### 注意

- `jre` 目录会显著增大安装包；
- macOS/Linux 的 java 可执行文件名不同（无 `.exe`）；
- 打包后 `backend.config.json` 的 target 仍是 java，除非用户改配置。
