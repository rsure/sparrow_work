# 领域文档（Domain Docs）

工程类技能在探查代码库之前，按这里的规则消费本仓库的领域文档。

## 探查前先读这些

- 仓库根目录的 **`GLOSSARY.md`**：领域术语表
- **`docs/adr/`**：与本次要动的区域相关的架构决策记录（ADR）

本仓库是**单上下文**布局：一个根级 `GLOSSARY.md` + 一份 `docs/adr/`。
没有 `GLOSSARY-MAP.md`，也没有各子包（`frontend/`、`electron/`、`backend/`、`backend_java/`）独立的术语表。

这些文件暂时不存在就**安静跳过**：不要提示「缺少文件」，也不要主动建议先建。
等真正敲定了术语或决策，再由 `/domain-modeling` 按需创建。

## 术语必须与 GLOSSARY 一致

输出里出现领域概念（工单标题、重构提案、假设、测试名）时，用 `GLOSSARY.md` 定义的说法，
不要换成它明确避免的同义词。

要用的概念还没进术语表，说明两件事之一：你在造项目并没有的词汇（先重新考虑），
或者确实有缺口（记下来交给 `/domain-modeling`）。

## ADR 冲突要显式指出

如果你的输出与已有 ADR 冲突，明确说出来，不要静默覆盖：

> _与 ADR-0007（event-sourced orders）冲突，但值得重新讨论，因为……_
